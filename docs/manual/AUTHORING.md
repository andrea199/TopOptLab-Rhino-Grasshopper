# Maintaining the TopOptLab manual

This is the canonical English manual. Start at `index.html`.

## One content tree

- `index.html`: manual home, generated from `tools/manual/build.py`.
- `components/index.html`: component reference, generated from `data/components.json`.
- `learnings/index.html`: course sequence, generated from `data/course.json`.
- `learnings/01-understand-the-problem/`: the first lesson, including slides, teacher guide, student sheet and native files.
- `assets/`: shared styles and component illustrations. Reuse these images instead of copying them into each lesson.
- `getting-started/index.html`: preparation and platform status.

## Add a lesson

1. Develop it directly in `learnings/NN-short-title/`. Use English for all student and teacher material.
2. Keep `index.html`, `slides.html`, `teacher-guide.html`, `student-sheet.html` and `files/` together. Omit files that the lesson does not need.
3. Add its title, duration, status, path and relevant component IDs to `data/course.json`. Change status to `available` only when the lesson files are ready.
4. Link to component explanations using `../../components/index.html#ComponentClassName`. Reuse illustrations from `../../assets/components/`.
5. From the repository root, run `python tools/manual/build.py`, then `python tools/manual/check.py`.
6. Review the changed pages in a browser. Test links, the lesson controls and narrow screens. Keep slides viewport-safe.

Future work belongs here. Do not create a separate lesson portal or dated ZIP for each update. A single whole-project export can be prepared when somebody actually requests a distributable release.

## Edit a component

Edit its English metadata in `data/components.json`, then rebuild. Input/output names and defaults must match the plugin. Connections must come from verified examples or source inspection. Shared rendered images are named after the C# component class.

The native image exporter is in `tools/manual/RenderComponents.cs`; `render_images.py` compiles and runs it against the locally installed Rhino SDK and GHA. Rendering is needed only when component visuals change. Reading the manual requires neither Python nor Rhino.

## Navigation

The build command adds the same Home / Components / Learnings / Getting Started navigation to all normal manual pages. These generated navigation blocks are idempotent: edit content, then rebuild. Presentation mode keeps its own compact controls and returns to the parent lesson.

The Learnings page is the single course registry. Planned blocks remain labelled Planned and do not link to empty lesson pages.

## GitHub and GitHub Pages

Commit `docs/manual/` and `tools/manual/` with the rest of the repository. All published links and assets use relative paths; no local usernames, runtime paths or external JavaScript dependencies are required.

For branch-based GitHub Pages, the `/docs` directory can serve this manual at `/manual/`. Alternatively deploy `docs/manual/` as the static site root using a Pages workflow. Choose repository visibility and publication settings when publishing is explicitly requested. This preparation does not publish anything.

Keep software installers in GitHub Releases or another distribution channel. Runtime environments, installers, ZIP exports, caches and test SDK libraries do not belong in this documentation tree.

## Verification limits

Native Grasshopper starter archives have SDK readback checks. Actual classroom Rhino/Grasshopper opening, geometry selection, preview and control interaction require the teacher preparation checklist. Mac plugin support remains a pilot pending native acceptance.

## Available lessons and content sources

All eight lessons are available. Lessons 01–06 share the introductory Rhino model through relative links. Lesson 07 reuses the existing prepared roof definition from the shared component examples; lesson 08 collects evidence and conclusions.

Lessons 01–02 retain their editable HTML pages. For lessons 03–08, edit `data/lesson-content.json`; `tools/manual/build_lessons.py` regenerates their lesson pages, slides, teacher guides and worksheets during the normal manual build. Generated lesson HTML should not be edited directly. The shared course styles are derived from the approved lesson 02 style by that renderer.

The component registry remains `data/components.json`; the course order, durations and component references remain `data/course.json`. The build adds lesson links back into the component guide and preserves one shared navigation. All eight lesson blocks plus the break total 180 minutes.

Native exercise files for lessons 03–06 are generated by `tools/manual/create_course_files.py` and `CreateCourseFiles.cs`. Their partly wired starters deliberately omit only the connections described in the corresponding lesson. The wired solutions still require selecting geometry and running the stages explicitly; they do not contain completed runtime jobs.

Numerical tables and cell diagrams for the introductory plate use actual Python-worker reference calculations. Reproduce them using `tools/manual/reproduce_intro.py --output <new-directory>`. The `data/intro-reference.json` file records the exact request. These numerical checks and SDK readback do not replace the teacher’s Rhino opening, selection, preview and control checks.

Verification: run `tools/manual/check.py` for all links and language, then `tools/manual/check_course.py` for course continuity, archived wires and reference arithmetic. Optional `tools/manual/check_course_browser.cjs` checks all 56 slides in five viewports and the student exercises; Playwright and Chrome are development dependencies, not manual dependencies.
